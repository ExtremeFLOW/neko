◆ shmem_check_thread_level()

subroutine comm::shmem_check_thread_level ( integer, intent(in)  provided)
private

Only the device backends need SHMEM_THREAD_MULTIPLE, where several host threads drive their own streams. On the host, gs_shmem issues every SHMEM call from the OpenMP master thread – which is the initial thread, the one that called shmem_init_thread – and only lets the team drive the puts when the library reports MULTIPLE, so no level is actually unusable. That matters in practice: Cray LIBSMA reports SHMEM_THREAD_SINGLE, and refusing anything below FUNNELED would rule out hybrid MPI+OpenMP runs there altogether.
